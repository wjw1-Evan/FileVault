# FileVault 商用化方案（分析与改造清单）

版本：v1.0 · 日期：2026-11-15 · 状态：商用核心已落到 v3.2.0（部分）

---

## 1. 结论

产品功能完整度已经达到「可卖」的工程基线（P0/P1 全量、140+ 自动化测试、自动更新、SF Symbols 原生 UI），但**真正挡住商用的是四件事，按优先级**：

| 优先级 | 阻塞项 | 现状 | 影响 |
|---|---|---|---|
| P0 | 签名与公证 | ad-hoc 签名，Gatekeeper 首次打开需右键；无公证 | 用户装不上/不敢装，无法上架 |
| P0 | 品牌名 | 「FileVault」与 macOS 磁盘加密同名 | 商标风险、搜索被系统功能淹没、App Store 审核风险 |
| P0 | 收费与授权 | 无试用、无激活、无购买链路 | 无法变现 |
| P1 | 更新包完整性 | 仅校验 GitHub API 返回的 sha256（同一来源） | 供应链被篡改时无法发现 |
| P1 | 法务文本 | 无 EULA / 隐私政策 | 无法合规售卖、支付渠道审核不过 |
| P1 | 支持体系 | 无诊断包、无反馈入口 | 客服成本高，退款率高 |
| P2 | 国际化 | 仅中文 UI | 失去海外市场 |
| P2 | 崩溃可见性 | 无崩溃上报（隐私允许的前提下） | 线上问题发现慢 |

> 已落地（v3.2.0）：许可/试用框架、诊断包、品牌常量收敛、EULA/隐私政策草案、发行签名脚本。

## 3. 商业模式建议

**渠道：官网直下载 + 支付平台代发授权（Paddle / Lemon Squeezy），不走 Mac App Store。**

原因：App Sandbox 会切断「任意目录 + 子进程 git」的组合，MAS 版本需要重写为 security-scoped bookmark 方案且仍需用户逐个授权，改造成本高、体验下降，且 MAS 抽成 15–30%。

**授权模型（推荐）**

| 版本 | 内容 | 价格建议 |
|---|---|---|
| 免费 | 1 个根目录、本地版本管理、历史/回滚 | ¥0 |
| Pro 买断 | 多根目录、自动推送、多机、统计面板 | ¥98–168 一次性，含 1 年更新 |
| 试用 | 全功能 14 天（已实现） | — |

技术要点（已实现）：授权码为 **Ed25519 离线签名令牌**，激活不依赖服务器；私钥只在发行方机器上（scripts/issue-license.swift），公钥内置应用。试用起始时间写钥匙串，删除应用重装不会重置试用。

**试用结束后的降级策略**（已实现）：停止「新建自动版本」，但**历史查看、单文件恢复、整仓回滚始终可用**——数据永远不锁死，这是信任底线。

## 5. 发布工程检查清单

1. swift test 全绿（当前测试项数以实际为准）
2. make_app.sh <版本> → 校验 CFBundleShortVersionString
3. 若配置了 CODESIGN_IDENTITY：codesign --verify --strict + spctl -a -vv 通过
4. 公证（NOTARY_PROFILE）：xcrun notarytool submit --wait → stapler staple
5. --smoke 自检通过
6. 打包 zip（ditto -c -k --keepParent），sha256 写入 Release 说明
7. 打 tag、推送、创建 Release、更新 README 下载链接
8. 灰度：先在旧版上验证一次自动更新端到端

## 6. 品牌与法务

- **改名**：候选 Vaultkeeper / TimeGit / SnapKeep / Histodeck；执行前做 USPTO/CNIPA 检索与 App Store 重名检查；改名范围 = AppBrand.swift + scripts/make_app.sh 的 CFBundle 字段 + README/文档 + 仓库名（可选）。
- **EULA**：见根目录 LICENSE（专有许可，禁止再分发/反向工程，数据所有权归用户）。
- **隐私**：见 PRIVACY.md——无遥测、无云端中转、凭证仅钥匙串、更新检查只访问 GitHub 公开 API。
- **开源合规**：若内嵌 git 二进制，需附 GPLv2 文本与源码获取方式；当前实现优先调用系统/用户已有 git，未分发 git。
- **出口合规**：使用 HTTPS/加密（CryptoKit），如上架需在 App Store Connect 声明。

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 试用被绕过（改系统时间） | 收入损失 | 关键路径读取单调时钟 + 服务器可选校验；不锁数据，降低破解动机 |
| 改名导致用户迁移成本 | 品牌资产损失 | 提前在发布说明中预告；bundle id 保持不变、配置目录兼容 |
| 公证失败 | 无法发布 | CI 中固定 notarytool 流程、保留 ad-hoc 兜底包 |
| 支付平台审核 | 上架延迟 | 提前准备 EULA/隐私/退款政策 |
