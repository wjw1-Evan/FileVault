## 一条记忆的格式

`@
### 结论：一句话说清是什么（≤ 30 字）

- 原因：为什么这么做，有什么取舍（1–3 句）
- 证据：`路径:行` / 提交哈希 / 日期
- 影响：什么情况下会再次遇到，怎么规避
`@

日期统一 `YYYY-MM-DD`。没有证据的记忆不要写——宁可先不记。

## 什么时候写

只有三种情况值得写：

1. **做了有取舍的决策**：两种做法都可行，选了一个，理由不在代码里。
2. **修了看不出来的 bug**：根因不直观，下次还可能踩。
3. **定了新约定**：命名、目录、错误文案、发布流程。

其余一律不写：过程流水账、代码里一眼可见的事实、临时状态。

## 什么时候读

- 开工前用关键词搜一次：`grep -rn "关键词" docs/memory/`
- 先看上面的索引，再打开命中的文件，**不要整目录通读**（会把上下文撑大）。
- 记忆与代码冲突时，以代码和 git 历史为准，并顺手修正记忆。

## 维护

- 过期就删或改写，不保留“历史版本”——git 已经替你留了。
- 单文件超过 200 行或索引超过 30 条时，按主题拆子目录。
- 密钥、令牌、个人身份信息一律不进这个目录。
