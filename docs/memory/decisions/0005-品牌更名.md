# 0005 · 品牌更名：FileVault → Pastward

- 状态：已采纳（随 v4.2.31 发布）
- 日期：2026-11-19
- 证据：`Sources/FileVaultCore/AppBrand.swift:19`、提交 `6b345d5`、`Tests/FileVaultTests/BrandTests.swift`、`docs/10-品牌更名方案.md`

## 背景

「FileVault」与 macOS 自带磁盘加密功能完全同名——搜索混淆 + App 审核风险（docs/04 标记的 P0）。约束：存量用户的自动更新链与本地数据不能断（无账号体系，迁移只能靠兼容）。

## 选项

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 保留 FileVault | 零改动 | 永久混淆与审核风险 |
| 换成常见词（Rewind/Timeline 类） | 直观 | 高频词检索不可达，且大多被占 |
| 造词 Pastward | 语义命中（回到过去）、商标性强、检索零冲突 | 需要向用户解释一次（Release 说明已覆盖） |

docs/06 原候选与 13 个常见词方案经四轮 web 检索全部撞名（矩阵见 docs/10 §2）。

## 决定

更名 **Pastward**（past + -ward）；**只改用户可见面**，机器标识（bundle id `com.filevault.FileVault`、配置目录 `~/Library/Application Support/FileVault`、`refs/filevault/backup`、模块/可执行名）刻意保留旧拼写。

## 后果

- 好的：搜索独特、审核风险消除；老用户自动更新完全无缝（更新器按版本号匹配资产、按 bundle id 校验，均不依赖品牌名——历代机制实证见 docs/10 §4.1）。
- 坏的：Finder 里自动升级用户的 .app 仍显示旧名（重装一次即换）；LICENSE/PRIVACY 品牌字样待法务确认后维护者自行更新。
- 后续：**每个 Release 只上传一个 `Pastward-<版本>.zip`**——两个同版本 zip 会触发 v4.2.30+ 的歧义拒绝守卫；GitHub 仓库改名前先实测旧版端到端更新；USPTO/CNIPA 正式检索仍是发布前置。未来任何"顺手统一机器标识"的改动都会破坏老用户升级，BrandTests 已立此存照。
