# 0002 · 更新包缺少 sha256 时拒绝安装（fail-closed）

- 状态：已采纳（v4.2.26）
- 日期：2026-11-16
- 证据：`Sources/FileVaultCore/SelfUpdater.swift:15`、`Sources/FileVaultCore/UpdateChecker.swift:40`、`Tests/FileVaultTests/UpdateTests.swift`

## 背景

GitHub Releases API 的 asset `digest` 字段缺失时，旧实现直接跳过 sha256 校验（fail-open）继续安装。分发包是 ad-hoc 签名，签名校验对无 Team ID 的包只校验 bundle id，因此「下载内容被替换/损坏」没有任何校验；README 又明确承诺「sha256 校验」。

## 选项

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 缺 digest 时跳过（旧） | 兼容 API 变更，更新不会因此中断 | 与文档承诺不符，完整性问题静默 |
| 缺 digest 时拒绝安装（新） | 完整性承诺真实，可提示用户手动下载 | 若 GitHub 停止返回 digest，自动更新会停 |

## 决定

拒绝安装并给出可读错误（`.missingChecksum`）。更新是安全敏感路径，宁可停止自动安装，也不安装未经校验的包。

## 后果

- 好的：完整性校验不能被 API 字段缺失绕过；测试锁定 fail-closed。
- 坏的：极端情况下自动更新暂时不可用，错误文案引导手动下载。
- 后续：若引入正式 Developer ID 签名，可在团队签名可验证时评估放宽 digest 要求。
