# 0001 · 一个受保护文件夹 = 一个 Git 仓库

- 状态：已采纳（v4.0）
- 日期：2026-11-16
- 证据：README:5、README:13

## 背景

早期版本把用户添加的文件夹按“一级子文件夹”拆成多个仓库。用户看到的是一个文件夹，实际下面有好几个 `.git`，历史、远程绑定、回滚范围都对不上，恢复文件时也很难解释“为什么这个文件不在这个仓库里”。

## 选项

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 按一级子文件夹拆仓 | 单仓小、推送快 | 心智复杂、历史割裂、远程要配多次 |
| 整个文件夹一个仓 | 与“文件时光机”的心智一致、历史完整、一次绑定 | 单仓更大，超大文件更容易触碰远端上限 |

## 决定

一个受保护文件夹就是一个 Git 仓库：根目录下所有文件（含多级子目录）都进这一个仓；文件夹本身已有 `.git` 则直接接管复用，不破坏。

## 后果

- 好的：历史与回滚粒度对齐用户认知；远程只绑一次；恢复逻辑只需面向一个仓。
- 坏的：单仓体积增长快。缓解手段——上限跟随远端（github.com 100 MB）、超限文件排除并通知、每周 `git gc --auto`。
- 后续：如果出现“单仓大到无法推送”的真实案例，再评估子仓或 LFS，不要提前拆。
