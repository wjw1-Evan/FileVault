# 10 · 品牌更名方案：FileVault → Pastward

版本：v1.0 · 日期：2026-11-19 · 状态：已执行（随 v4.2.31 发布上线）

---

## 1. 决策结论

产品更名为 **Pastward**（past + -ward，"通往过去的方向"，中文释义「回到过去」）。原「FileVault」与 macOS 自带磁盘加密功能（FileVault）完全同名，存在搜索混淆与 App 审核风险（docs/04 风险与竞品分析早已标记为 P0 阻塞项）。更名仅涉及**用户可见的产品名**；全部机器标识（bundle id、配置目录、备份 ref、模块与可执行名）刻意保留旧拼写，存量用户自动更新与数据迁移零感知。

## 3. 为什么是 Pastward

1. **语义精确命中**：产品唯一使命是"把文件带回过去"——历史时间线、找回删除、还原旧版，全部是 pastward 方向的动作；与 README 既有的「文件时光机」定位天然呼应。
2. **造词商标性最强**：仿 backward / afterward / homeward 的构词法，是一个可读、可念、但词典里不存在的品牌词，天然避开常见词与既有商标的密集区。
3. **搜索独特性**：低频词，将来用户搜索 "Pastward" 直达本产品；不像 Rewind / Timeline 一类高频词会被淹没。
4. **界面观感**：「退出 Pastward」「关于 Pastward」「Pastward 设置」干净自然，zh UI 无需翻译即可理解。

## 4. 兼容性设计（核心：老用户无感升级）

**刻意保留旧拼写的机器标识**：

| 标识 | 值 | 为什么不动 |
| --- | --- | --- |
| bundle id | `com.filevault.FileVault` | UpdateGuard 更新包校验钉住它；改动即断自动更新链 |
| 配置目录 | `~/Library/Application Support/FileVault` | 存量用户的受保护文件夹列表、远程绑定全在这里 |
| 备份 ref | `refs/filevault/backup` | 回滚找回依赖既有 ref 历史 |
| 模块/可执行名 | `FileVaultApp / FileVaultCore / FileVaultTests` | 纯代码标识，无品牌露出 |
| UserDefaults 键 | `fv.*`、`fv.onboarded` 等 | 配置兼容 |
| 更新仓库名 | `wjw1-Evan/FileVault` | 在野更新器钉住它（见 §4.1） |

**用户可见面**：窗口标题、菜单行、关于面板、系统通知、FAQ、诊断包名（`Pastward-诊断-*.zip`）、支持邮件主题、git 镜像名等全部换新（提交 6b345d5）；en.lproj 键值同步（LocalizationTests 强制校验），并有 BrandTests 5 项契约测试钉住"不得回潮"。

### 4.1 自动更新机制实证（读了 UpdateChecker 与历代发布版源码，非推测）

| 在野版本 | 资产匹配逻辑 | 对 `Pastward-<版本>.zip` 的兼容性 |
| --- | --- | --- |
| v3.4.2 及更早 | `assets.first { name.hasSuffix(".zip") }`——取第一个 zip，不看名字 | ✅ 任意名都能更新（且 v3→v4 本就是破坏性升级，README 已声明） |
| v4.2.27–v4.2.29 | `allZips.filter { name.contains(版本号) }`，单 zip 兜底 | ✅ 版本号子串匹配，不依赖品牌前缀 |
| v4.2.30+（现行） | 版本号子串 + 数字边界防歧义（`"4.2.3"` 不再误配 `"…4.2.31.zip"`），单 zip 兜底，**多个 zip 同含版本号 → noAsset 拒绝更新** | ✅ 单一 `Pastward-4.3.0.zip` 正常匹配 |

> **⚠️ 由此推翻一个直觉方案：不要同时上传 `FileVault-x.zip` 与 `Pastward-x.zip` 两个资产。** 两个 zip 都含版本号，会命中现行版本的"歧义拒绝"守卫（matched>1 → 拒绝更新），反而把所有 v4.2.30+ 用户堵在门外。**每个 Release 只上传一个 zip**，命名 `Pastward-<版本>.zip` 即可——旧版更新器都能找到它。

### 4.2 更新安装路径

SelfUpdater 动态定位解压目录里的 .app（不硬编码名字，SelfUpdater.swift:69），更新包校验只钉 bundle id 与 Team ID——所以自动升级后 .app 文件夹在 Finder 里仍显示旧名 FileVault.app（功能完全正常），**重装一次新包即换成 Pastward.app**。此差异已在 Release 说明与 README 的升级指引中写明。

### 4.3 仓库改名

GitHub 仓库改名后，API 与资产下载链接会 301 重定向，理论上在野更新器仍可用；但**建议暂不改仓库名**（`UpdateChecker(repo: "wjw1-Evan/FileVault")` 在各在野版本中是硬编码默认值），或在改名前用一台装着旧版本的机器实测一轮端到端自动更新。

## 5. 商标与法务前置

本轮尽调为 **web 级四轮检索**（软件产品 / App Store / GitHub / 域名观感）。正式商用发布前，**USPTO / CNIPA 商标检索仍是维护者的必要前置步骤**，注册类别建议覆盖第 9 类（计算机软件）。LICENSE 与 PRIVACY.md 的品牌字样改动留给维护者走法务流程确认后自行提交。
