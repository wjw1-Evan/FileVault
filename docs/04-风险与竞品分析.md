# FileVault 风险与竞品分析

版本：v1.1 · 日期：2026-11-14

## 1. 命名风险（高优先级）

**FileVault 与 macOS 自带的磁盘加密功能同名**，存在搜索混淆与 App Store 审核风险。候选名：Vaultkeeper / TimeGit / SnapKeep / Histodeck。

- 短期（个人项目阶段）：保留 FileVault，文档已标注风险。
- 发布前：建议评估改名并做商标检索。

## 2. 远程同步风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| HTTPS 凭证 | 密码/Token 泄漏 | 凭证只存钥匙串（osxkeychain credential helper），App 不经手密码 |
| 远程仓库未预先创建 | push 失败 | 配置远程时连通性测试（FR-17）；文档指引先建仓 |
| 敏感文件上云 | 隐私泄漏 | 首次配置远程检查清单：敏感文件提醒 + .gitignore 检查 |
| 大仓库首推慢 | 用户以为卡死 | 后台串行队列 + 进度展示 |
| 多机并发改动 | push 冲突 | 不自动 merge，向导处理（P1 拉取向导） |
| 内嵌 git GPLv2 | 许可证合规 | 开源本项目或分发时附带 GPL 声明与源码获取指引 |
| xcode-select 体积大 | 安装慢 | 内嵌 git 为默认路径，离线可用；未内嵌时走 5 个镜像下载（63 MB，sha256 校验），CLT 仅兜底（见 `docs/07`） |

## 3. 技术风险矩阵

| 风险 | 影响 | 缓解 |
|---|---|---|
| 提交风暴 | 历史噪音/性能 | 防抖 5s + 最大等待 60s |
| .git 膨胀 | 磁盘占用 | 每周 gc；大文件走 .git/info/exclude |
| iCloud/网盘目录 | 事件重复/同步竞态 | 监控层去重；文档提示风险 |
| 权限失败 | 无法监控 | NSOpenPanel 授予访问；失败显式报错 |
| 仓库被手动改坏 | 自动提交失效 | git status 兜底自愈 + 状态机可见 + 菜单「立即提交」 |
| GitHub 100 MiB 单文件限制 | 大文件 push 被拒、仓库永久膨胀 | 提交前按 GitHub 口径排除 + push 前预检 + 历史清理指引（见 [05 方案](05-GitHub-100MB限制解决方案.md)） |
| 单仓库故障域（v4.0） | 一个大文件或一次 push 失败会影响整个文件夹的云端备份 | 本地提交永远先行；超远端上限的文件自动排除；push 失败指数退避重试且状态在菜单可见 |
| 测试依赖真实网络 | CI 不稳定 | 全部测试用本地裸仓作远程，不依赖真实网络/账号 |

## 4. 竞品对比

| 竞品 | 形态 | 普通用户门槛 | 版本粒度 | 远程备份 |
|---|---|---|---|---|
| Time Machine | 系统备份 | 低（需备份盘） | 快照粒度粗 | 无 |
| gitwatch（开源脚本） | 脚本 | 高（需终端） | 文件级 | 手动 |
| GitButler/Tower/Fork | 开发者 GUI | 高 | 文件历史 | 手动 |
| 坚果云/Dropbox | 网盘 | 低 | 粒度粗、保留期短 | 网盘 |

**差异点**：FileVault 零门槛（自动准备 git）+ 整个文件夹一个仓库（含根级散落文件与多级子目录）+ 每个文件夹可独立绑定远程上云 + 本地优先。

## 5. 商业模式建议（远期）

- 免费版：单根目录 + 本地版本管理
- Pro（一次性买断）：多根目录、远程备份、统计面板
- 本阶段：个人项目，全功能免费，先验证价值
