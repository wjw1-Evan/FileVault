# Pastward

**给普通人的文件时光机 — 基于 Git 的 macOS 菜单栏自动版本管理工具**（原名 FileVault，v4.2.31 起更名）

Pastward 常驻 macOS 菜单栏，对你添加的每个文件夹，**直接在该文件夹根上初始化一个 Git 仓库**（v4.0 起不再按一级子文件夹拆仓）；监控到文件变动后自动提交。核心价值：**零操作的文件历史版本管理**——误删误改随时找回，可选绑定远程仓库自动备份上云。

> ✅ 品牌决策（v4.2.31）：原「FileVault」与 macOS 自带磁盘加密功能同名（搜索混淆 + 审核风险），正式更名为 **Pastward**（仿 backward / afterward 构词，"驶向过去"，与「文件时光机」同构）。更名经全网冲突检索：无任何同名软件产品、App Store 应用或活跃 GitHub 项目占用（原候选 Vaultkeeper/TimeGit/SnapKeep/Histodeck 均已证伪撞名）。**机器标识刻意保留旧拼写以保迁移连续**：bundle id `com.filevault.FileVault`（自动更新链钉住它）、配置目录 `~/Library/Application Support/FileVault`、备份 ref `refs/filevault/backup`、可执行与模块名 `FileVaultApp/FileVaultCore`——老用户自动更新完全无缝，重装一次即可换成新名的 .app。完整尽调矩阵与历代更新器兼容实证见 [docs/10-品牌更名方案](docs/10-品牌更名方案.md)。

## 核心功能

1. **零配置起步** — 首次启动自动检测 Git 环境；缺失时自动安装：**内嵌 git（零下载）→ 5 个下载镜像逐个尝试并 sha256 校验 → 最后才回退 Xcode CLT**，全程无需命令行。下载地址与实测速度见 [docs/07-Git自动安装与镜像源.md](docs/07-Git自动安装与镜像源.md)。
1.5 **一步添加文件夹（v4.2.18；v4.2.30 支持拖拽）** — 首次启动、菜单栏、主面板三处的「添加文件夹…」都打开同一个添加窗口：选好文件夹即完成保护；若该文件夹已有 git 远程地址会自动填入，也可以直接粘贴远程地址一起绑定，或先留空以后再在设置里加。**v4.2.30 起把文件夹直接拖到菜单栏弹层或主面板的文件夹卡片上即可添加**（添加窗口自动带出路径，已受保护的文件夹会弹回）；表单去掉了 git 术语（「云端备份（可选）」），并内置「在 GitHub 创建并绑定」私有仓库一键创建（gh 未安装时会就地说明）。首启引导不再因一次「取消」而永久消失：添加成功才算完成引导；Git 自动安装失败时表单如实显示原因与查看入口，不再让你「稍后重试」一个死胡同。不再需要「打开设置 → 添加文件夹 → 找到远程配置 → 输入 → 保存」四步。
2. **整个文件夹一个仓库** — 文件夹位于 iCloud Drive / Dropbox / OneDrive / Google Drive 等云盘目录时，设置页会提示「按需下载可能被误判为删除」（占位符文件在 git 看来像被删），建议改用本地文件夹或关闭按需下载（v4.2.13）。配置有自动备份：`config.json` 损坏时自动从上一份可用备份恢复受保护文件夹列表并通知你，损坏文件会保留为 `config.corrupt-*.json` 便于排查（v4.2.12）。文件名含空格、换行、引号甚至「->」等特殊字符也能被正确识别与提交（Git 状态/文件列表用 NUL 分隔解析，不会把重命名拆错，v4.2.10）；提交说明里的文件名会自动压成一行、超长名字截断，不会把历史界面撑乱（v4.2.11）。文件夹不可用（外置盘未挂载、被移走）时，设置页会明确显示「⚠️ 文件夹当前不可用」而不是「0 次提交」；如果受保护文件夹的 .git 意外丢失，启动时会通知「已重新初始化为空历史」并提示重新填写远程地址，不会悄悄变成空仓库（v4.2.8）。**同时运行两个 Pastward（比如「应用程序」里的旧版和设置里的新版）时，每个文件夹只会被第一个运行中的实例管理**，另一个实例会显示「另一个 Pastward 实例正在管理」且不会重复提交/推送；前一个实例退出后会自动接管（v4.2.9）。文件夹被移动/改名（或外置盘挂载路径变化）时，可在「更多 → 重新定位（文件夹被移动/改名）…」指到新位置，Git 历史、暂停状态与远程绑定都保留（v4.2.5）。添加一个文件夹，它本身就是一个 Git 仓库：根目录下的散落文件、多级子文件夹、隐藏目录（除 `.git` 与忽略规则外）全部纳入版本管理；文件夹本身已有 `.git` 则原样接管复用，绝不破坏（文件夹内部嵌套的 `.git` 属于用户自己的项目仓库，不递归接管）。
3. **自动版本管理** — FSEvents 监控文件变动，5 秒防抖聚合后自动 `add + commit`，提交信息自动总结变更（如 `auto: 3 处变更 (+120 -40)，新增 a.md，修改 b.md`）。另有约 2 分钟一次的**安全巡检**兜底：即使 FSEvents 漏了事件（休眠唤醒、事件队列溢出、监听重启），也会补提交，不会让改动一直悬着；**启动时还会补交上次退出前没来得及提交的改动**（5 秒防抖可能还没触发就退出了，v4.2.15）；外置盘掉线重连或监听停止后会自动恢复监听；被单独暂停的文件夹自动跳过（v4.2.4/v4.2.7）。自动提交是**始终开启**的：应用不提供关闭开关（v4.2.22）。 新建的空文件夹会放入一个隐藏的 `.gitkeep`（Git 不记录空目录），让文件夹本身也进入版本历史、回滚时可一并还原。
4. **远程仓库自动同步（v4.2：只留自动同步）** — 每个受保护文件夹可单独配置远程地址（GitHub/GitLab/Azure DevOps 等）与**身份验证**（自动 gh 凭证助手 / 用户名+访问令牌 / SSH 密钥，凭证写进本机钥匙串、不进 git 配置）。保存地址即开启同步，之后**全自动、没有任何手动入口**：本地提交后自动推送；被远程新提交拒绝时先自动快进或变基再重试，永不强推；绑定一个已有内容的远程（或更换远程）时，自动把两边无损合并——远程独有的文件下载到本地、本地独有的文件原样保留、同名不同内容的两份都留（本地版本沿用原名，远程版本另存为「远程副本」）——随后自动推回去。「立即推送 / 拉取远程更新 / 强制拉取 / 同步远程文件到本地」四个手动入口和「提交后自动推送」开关已删除；升级后旧的「自动推送关闭」配置会在启动时自动转为开启。**.git 文件夹属于其他账户或位于外置盘时自动信任该文件夹（不再被「dubious ownership」卡住）；有多个远程时可在「更多 → 同步使用的远程」里选用哪个（v4.2.1）**。**推送被拒时若遇到同名文件冲突或远程历史完全不相关，自动改用「保留双方文件」的无损合并（同名两份都留）再推送，不再停在通知上；自动提交失败（磁盘满/权限/锁文件）用可读原因通知并自动重试 3 次（v4.2.2）**。**后台同步禁用交互式凭证/SSH 提示（缺凭证时立即给出可读错误而不是卡住或弹窗），网络抖动时一次故障只通知一次（重试静默，最终放弃会再通知说明已重试次数）（v4.2.3）**。**定时从远程同步（v4.2.17）：启动时立即检查一次，之后每约 5 分钟检查远程是否有新提交——有就自动拉取（能快进就快进、双方都有提交则自动变基、同名冲突则无损合并保留双方），本地领先则自动推送，不需要你点任何按钮**。**首次推送大仓库超过常规超时（120 秒）时自动改用更长预算（最多 10 分钟）重试一次（v4.2.7）**。**失败按类型给出可执行说明并通知**：分支名不一致会列出远程实际分支并给出设置上游命令，分支保护/仓库规则/只读或已归档仓库/文件过大拒绝只通知一次并停止重试，index.lock 占用给出清理指引，网络命令超时 120 秒并转为可读提示（v4.1.7）；**凭证过期/认证失败每 6 小时巡检一次并去重提醒**；**被忽略的本地文件（如 .DS_Store）在合并时若远程也新增了同名文件，会先另存为「本地副本」，不会被静默覆盖丢失**；**崩溃/强退残留的合并或变基可在「更多 → 修复未完成的合并/变基…」一键清理（不丢已提交历史与文件）**（v4.1.8）。
5. **菜单栏常驻** — 状态图标实时反映整体状态（空闲/同步中/待推送/异常）；菜单只保留一行摘要「N 个文件夹 · 正常」+ 每个受保护文件夹一行（状态点 + 状态词）+ 常用操作，详情都在主面板/设置里（v3.1.5 精简，不再堆砌健康度文字与版本号）。**v4.2.19 再精简**：去掉与自动提交重复的「立即提交」；**v4.2.20 合并入口**：菜单只剩「历史与恢复… / 设置」+「检查更新 / 关于」+ 退出；**v4.2.30**：主面板从「标题旁无文字图标」升级为带标签的「主面板…」行（⇧⌘D 不变），零文件夹时状态行如实说「尚未保护任何文件夹」、空文件夹卡本身就是「添加第一个文件夹…」按钮并可接受拖拽；**v4.2.22 去掉「自动提交已开启」开关**：自动提交始终开启、不可关闭，菜单里不再有让人犹豫的暂停开关；**v4.2.24 工具行对齐**：「检查更新 / 关于」从两个大块方块改成与「历史与恢复 / 设置」一致的紧凑行，视觉上更整齐；设置里每个文件夹的「认证方式」默认折叠为一行「认证：自动」，只有需要令牌或 SSH 时才展开。
6. **历史时间线** — 按天分组的提交时间线 + 本地搜索；选中任意版本可**预览其中文件**（文本与图片内联显示，PDF 等其他二进制用默认应用打开）。详情区可在「变更」与「全部」之间切换：**全部**展示该版本完整的文件树（含未改动的文件，可预览/打开/恢复），不再受“本次提交改了什么”限制。单个文件还能打开它自己的版本时间线（每行可直接恢复）、做任意两版本对比、看逐行差异与逐行归属（blame）；右上角菜单可导出该版本、给版本命名（标签）、恢复整个子目录，以及找回被回滚的版本。这里适合“看历史、回退整个文件夹”；按文件找回/还原请用下面的「文件恢复」窗口。
6.5 **快速打开** — 菜单栏与设置窗口均可一键在 Finder 中打开已添加的目录。
6.6 **主控面板** — 菜单标题栏的「打开主面板」图标按钮：状态总览 + 跨仓库最近活动流 + 目录卡片；窗口按内容自适应，单屏完整显示无滚动条（v3.4.1）。
7. **文件恢复（v4.1 重新设计，v4.2.20 合并窗口，v4.2.30 术语统一）** — 「历史版本」与「恢复文件」现在合并在同一个窗口的两个标签页里（**文件恢复 / 历史时间线**，v4.2.30 起全应用统一这两个叫法，旧的「找回与还原」指路全部接到真实控件），菜单也只剩一个「历史与恢复…」入口：不需要先想“我该开哪个窗口”，切换标签页也不会丢掉已选文件夹与版本。**「恢复」只做两件事：****找回被删除的文件**、**把改过的文件还原到以前的版本**。行内「恢复」会先弹确认（写明目标文件与版本，找回已删除文件保持一键直达）；「文件恢复」标签页按**文件**组织而不是按提交：左边自动列出**已删除**的文件和**最近修改**的文件（也可切到「全部」按文件名/路径搜索）；选中文件后，右边是它自己的版本时间线（日期 + 提交说明 + 短哈希），可预览当时内容、切到「与当前对比」看差异、用默认应用打开，或一键**恢复到此版本**。恢复只影响这一个文件：恢复前自动保存未提交改动，恢复本身也记成一个新版本（`restore: 找回/还原 …`），之后仍可再回退。**整个文件夹的回滚**作为破坏性操作留在历史窗口：仅回退本地当前分支，远程不变；忽略项、大文件与嵌套仓库保持原样；回滚前状态备份到隐藏 ref（`refs/filevault/backup`，可用 git 找回）。不存在的文件/版本会明确报错而不是静默失败（v3.3.1；恢复核心 45 项专门测试覆盖）。找回被删文件夹里的文件会自动重建父目录；如果原路径现在是一个文件夹，会提示先改名/移走而不是覆盖它（v4.2.14）。整个文件夹回滚前会检查里面有没有**未纳入版本管理的文件**（如 .env）：有则拒绝回滚并列出文件，绝不静默删掉（v4.2.16）。
8. **忽略规则** — 自动注入 .gitignore 模板（.DS_Store、node_modules 等），设置窗口内可视化编辑，改动会被自动提交。
9. **大文件保护** — 单文件上限**跟随远端**（无本地阈值设置）：github.com 远端自动按 100 MB 硬限制排除文件，其他远端不设限；设置页按仓库展示远端上限，避免仓库膨胀或推送必然失败。被排除的文件**不会悄悄消失**：首次排除时会弹通知说明「超过远程单文件上限、不会同步」，设置页健康信息也会显示「⚠️ N 个大文件未同步」，提醒你这些文件没有备份（v4.2.6）。
10. **按文件夹暂停** — 单个文件夹可单独暂停/恢复自动提交（例如搬运外置盘期间），恢复时自动补一次提交；**应用整体不再提供关闭自动提交的开关**（v4.2.22：自动提交始终开启）。
11. **测试连接** — 一键验证**输入框里正要保存的地址**（v4.2.30：此前测的是上一次已保存的旧地址）；失败原因走分类后的可读文案（地址有误 / 无权限 / 网络不可达），git 原始输出只作悬停详情；地址明显不完整（缺 https:// 或 git@ 开头）会在保存前就地提示。
12. **仓库健康度** — 设置窗口展示每仓库提交数 / 体积 / 最近提交时间；超过 2GB 告警。
13. **每周自动 gc** — 仓库每周自动 `git gc --auto`，控制 .git 膨胀。
14. **SSH 密钥引导** — 配置 SSH 远程时检测 ~/.ssh 密钥，缺失时给出指引。
15. **失败系统通知** — 自动提交/推送失败时发送系统通知（本地提交永远先行，失败不影响本地版本管理）。
16. **中英双语界面** — 设置 → 语言 可切换「跟随系统 / 简体中文 / English」，默认匹配 macOS 语言；切换后自动重启应用生效（v3.4.0，含 200+ 条人工翻译与完整性测试）。
17. **帮助与支持（v4.2.30）** — 设置 → 关于与支持 内置 8 条常见问题（离线双语：误删找回 / 为什么没有保存按钮 / 大文件未同步 / 云盘文件夹 / 暂停语义 / 换机迁移 / 认证方式 / 求助路径）；「反馈与支持」一键发邮件，主题自动附上应用与系统版本，配合脱敏诊断包即可自助求助——补齐商用化方案点名的支持体系缺口。

## 典型场景

| 场景 | Pastward 的价值 |
|---|---|
| 论文写作误删一整章 | 主面板「恢复文件」按钮或「历史与恢复…」窗口的「文件恢复」标签页 → 已删除里找到它 → 一键找回 |
| 设计稿改坏了想反悔 | 最近修改里选中文件，还原到改坏前的那个版本 |
| 一整批改动都不对 | 历史窗口把整个文件夹回滚到之前的提交 |
| 笔记库多机使用 | 每个受保护文件夹一个私有远程仓库，提交后自动推送，多机同步备份 |

## 系统要求

- macOS 14.0+
- Apple Silicon（官方发布包为 arm64；Intel Mac 可从源码构建：`swift build -c release`，首次运行会下载对应架构的 git）
- 无需预装 Git（应用会自动准备）

## 自动更新

应用内置更新器（FR-20）：启动 **20 秒后**静默检查一次 GitHub Releases，之后**每小时一次**；检查失败 **10 分钟**后重试（并显示失败状态）；设置里重新打开「自动检查更新」会立即恢复检查（v3.1.4），**发现新版本自动下载安装并重启**（受「自动检查更新」开关门控）。安装流程：字节级下载（实时百分比+字节数）→ sha256 校验 → **更新包签名/身份校验**（v3.3.0：校验 bundle id 与代码签名，正式签名版还会钉住 Team ID）→ 原子替换 bundle（旧版保留 `.old` 可回滚）→ 自动重启。**启动失败自动回退**（v3.3.0）：新版本连续 3 次未能正常启动时，自动换回上一版本并通知。仅 `.app` 包内运行时可用。

**进度只在菜单里看（v3.1.7）**：更新不再弹出任何窗口或对话框。打开菜单栏图标即可看到一行实时状态——`正在下载更新 42%… · 840 KB / 2 MB` → `正在校验更新…` → `正在安装更新…` → `更新完成，正在重启…`；手动「检查更新…」的结果也写在菜单里（如 `已是最新版本（v3.1.5）`、`更新失败：…`），不会打断你正在做的事。

## 仓库卫生：GitHub 100 MiB 限制

GitHub 对普通 Git 仓库的单文件有 **100 MiB 硬限制**（50 MiB 起警告，超限直接拒绝 push）。本仓库约定：构建产物与发布包一律不进 Git，二进制分发只走 Releases。新克隆请执行一次：

```bash
./scripts/install-git-hooks.sh   # 启用 pre-commit 守卫（阻止 > 100 MiB 文件）
./scripts/check-large-files.sh   # 手动全历史体检
```
